# 周末有解 · 上海城市玩法盲盒

一款原生微信小程序 MVP：用户选择想要的体验，抽取一个具体的上海城市挑战；完成并评价后，推荐会逐渐贴近用户偏好，同时保留盲盒的意外感。

## 已实现

- 上海限定玩法盲盒，体验标签可选
- 一次只揭晓一个具体任务，减少选择困难
- 每个周末最多收下4个挑战，可自由切换、完成或放回
- 完成后的快速评价、标签反馈和一句话记录
- 本地探索档案、区域统计、成就印章和城市人格
- 每完成4个挑战升一级，等级无上限
- 基于真实反馈的轻量个性化推荐（70%偏好、20%邻近探索、10%随机惊喜的产品原则）
- 500条以上可推荐上海自助玩法，覆盖400个以上官方名录及官方介绍中的地点
- 5个主题严格筛选：放空治愈、新鲜刺激、文艺漫游、户外出汗、夜间出逃，另有随机盲盒
- 全上海16区与5个主题均可多选，记住上次选择；地区展开每行3项，主题保持每行2项
- 同一维度取并集，地区与主题共同筛选；“全上海”和“随机盲盒”分别取消地区、主题限制；无匹配会提示
- 每条活动包含官方来源、名录核对日期和地址；有核实坐标可导航，其余复制地址到地图搜索
- 云端活动目录与本地离线兜底

## 在微信开发者工具中运行

1. 安装并打开微信开发者工具。
2. 选择「导入项目」。
3. 选择本仓库所在文件夹。
4. 使用你的小程序 AppID；仅查看界面时也可以选择测试号。
5. 点击「编译」。

## 本地校验

推荐逻辑没有第三方依赖，可直接运行：

```bash
node tests/recommend.test.js
node tests/app-state.test.js
node tests/cloud-sync.test.js
node tests/catalog.test.js
node tests/filters.test.js
node tests/miniprogram-startup.test.js
node scripts/build-cloud-catalog.js --check
```

## 项目结构

```text
pages/index       玩法盲盒
pages/challenge   本周挑战与完成反馈
pages/explore     探索档案与城市人格
data/plays.js     上海玩法离线目录
data/catalog.js   真实地点、来源与任务生成规则
utils/recommend   推荐与画像逻辑
cloudfunctions    用户状态同步与活动目录函数
```

## 开通云数据库同步

1. 在微信开发者工具顶部点击「云开发」，创建或选择一个云环境。
2. 在开发者工具中右键 `cloudfunctions/syncState`，选择「上传并部署：云端安装依赖」。
3. 同样部署 `cloudfunctions/getPlays`。
4. 重新编译。云函数首次运行时会自动创建 `user_states` 和 `plays` 集合。

小程序始终先写入本地缓存；网络或云函数暂时不可用时，核心流程仍可继续使用。云端文档以微信 OPENID 隔离，客户端不直接访问数据库。

## 活动真实性

活动地点来自上海市文旅局、上海市政府、上海市绿化市容局、上海图书馆和上海市文旅推广网等官方来源。大模型只用于生成玩法任务；地点、地址、开放说明和来源必须通过 `tests/catalog.test.js` 校验后才能发布。开放时间、收费和临时闭馆仍可能变化，小程序会提示用户出发前查看官方来源。

### 目录升级（2026-10）

`node scripts/import-official-places.js` 从6份官方名录提取名称、所属区、地址、已有开放说明，处理合并单元格并去重。`data/curated-activities.js` 补充攀岩、滑雪、卡丁车和夜游目的地，均附官方介绍链接。

这里的数量指“地点＋具体自助任务”，不是同数量的独立商家、实时场次或已经向每家电话确认的营业信息。同一公园可以有安静休息和快走训练两条不同任务；不生成不存在的限时展览、讲座或课程承诺。公园名录部分较早，目录核对日期不等于今天仍营业，出发前须确认；未取得坐标不填充行政区中心点。

修改后运行 `node scripts/build-cloud-catalog.js` 生成客户端可加载的 `data/official-places.js`、云函数种子和旧版活动迁移清单。JSON原始快照仅供构建脚本使用，客户端不可直接 `require` JSON。部署 `getPlays` 后首次调用会分批补充新数据、归档旧版混合主题活动。旧记录不删除，已采纳挑战与印章继续保留。首次初始化若超时可重试（已经导入的记录不会重复插入），建议云函数超时设置为60秒。

旧版客户端继续收到兼容的100条旧目录，不会因新目录缺少部分坐标而中断地图功能。新版请求携带目录版本号，触发新版目录迁移；云函数和前端可分步部署。

最后上传小程序新版本，提交代码审核，通过后发布；已发布的旧版不会因为本地文件更新而自动更新。
